# HSBC Fraud Detection (Autoencoder)

This repository contains an autoencoder-based fraud detection example. The project trains an autoencoder to model normal (non-fraudulent) credit-card transactions and uses reconstruction error as an anomaly score to detect fraud.

## What this project includes

- `ml.ipynb` — Jupyter notebook containing the full training pipeline, model definition (an autoencoder), training/validation split, threshold selection, evaluation, and artifact saving.
- `app.py` — (Streamlit) app for serving the trained model (if present). Open with `streamlit run app.py`.
- `requirements.txt` — Python dependencies used by the project.
- `simple_fraud_data.csv` — small synthetic dataset generator output (also included/generated by a notebook cell).
- `fraud_autoencoder.keras` — model artifact produced by training (saved to project root when training completes).
- `fraud_metadata.pkl` — pickled metadata (scaler and selected threshold) saved alongside the model.

## High-level overview

1. The autoencoder is trained only on normal transactions (Class == 0) so it learns to reconstruct normal behaviour.
2. At inference, reconstruction mean squared error (MSE) per sample is used as an anomaly score.
3. A threshold is chosen using a validation split and maximizing F1-score on a held-out threshold set.
4. Predictions are generated by comparing the anomaly score to the selected threshold.

## How to run (recommended)

1. Create a virtual environment and install dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

2. Open the notebook and run all cells (training will save artifacts):

 - Launch Jupyter Lab or Notebook:

```bash
jupyter lab
# or
jupyter notebook
```

 - Open `ml.ipynb` and run the cells. The training cell saves two artifacts to the repository root:
  - `fraud_autoencoder.keras`
  - `fraud_metadata.pkl`

3. Alternatively, generate the small synthetic dataset included in the notebook by running the synthetic data cell (this creates `simple_fraud_data.csv`) and update the dataset filename in the notebook if you want to test quickly.

Note: the notebook expects a file named `creditcard.csv` by default. If you only have `simple_fraud_data.csv`, either rename it to `creditcard.csv` or edit the notebook `pd.read_csv(...)` line to point to `simple_fraud_data.csv`.

## Run the app (if model artifacts available)

If you have trained and saved the model artifacts, start the Streamlit app:

```bash
streamlit run app.py
```

The app will attempt to load `fraud_autoencoder.keras` and `fraud_metadata.pkl` from the project root.

## Notes & recommendations

- Large binary artifacts: `fraud_autoencoder.keras` and `fraud_metadata.pkl` can be large. If you don't want them in git history, add them to `.gitignore` before committing, or use Git LFS:

```
fraud_autoencoder.keras
fraud_metadata.pkl
```

- The notebook uses `StandardScaler` for preprocessing. The scaler instance is saved inside `fraud_metadata.pkl`. Keep `fraud_metadata.pkl` alongside the model when deploying.

- If you push to GitHub over SSH, ensure your SSH key is added to your GitHub account. If you prefer HTTPS, set the remote to the HTTPS URL and use a Personal Access Token (PAT) when prompted.
